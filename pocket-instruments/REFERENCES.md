| R33 | VCV's Panel Guide, read 2026-11-19. A panel is an SVG in mm, 128.5 mm tall and a multiple of 5.08 mm wide. All text must be converted to paths; complex gradients are unsupported and simple two-colour linear ones "may work"; CSS is unsupported beyond inline fill and stroke. Component graphics are not drawn on the panel: placeholders go on a hidden layer named `components` (param red `#ff0000`, input green `#00ff00`, output blue `#0000ff`, light magenta `#ff00ff`, custom widget yellow `#ffff00`), which Rack's helper script reads. Advice: design as if for hardware, leave room for thumbs between knobs and ports, use an inverted background for output ports, keep labels succinct, roughly follow the density and text sizes of VCV's own modules, and keep text readable at 100% on a non-high-DPI monitor. It names no font, size or spacing in numbers. It says not to use others' intellectual property without permission | https://vcvrack.com/manual/Panel |

| R34 | VCV's Voltage Standards, read 2026-11-19. Audio outputs are typically ±5 V; nothing should exceed ±12 V, and hard clipping is discouraged. A trigger source sends 10 V for 1 ms; a gate is 10 V while active. A trigger input is a Schmitt trigger, low about 0.1 V and high about 1 to 2 V. A module with CLOCK and RESET inputs should ignore CLOCK for 1 ms after a RESET. A cable carries up to 16 channels; a module with polyphonic ports takes the `Polyphonic` tag. A module that could produce NaN or infinity should output 0 | https://vcvrack.com/manual/VoltageStandards |

| R35 | VCV's Plugin API Guide, read 2026-11-19. Port and light tooltips append the words input, output and light, so labels in code leave them out. Since Rack 2.4 a module may offer a second, dark panel; a panel that is already dark can ignore this. ⚠ It says static text can be written on SVG panels, which contradicts R33; we follow R33 and outline the text. It has no rules on a module's name or look for the Library | https://vcvrack.com/manual/PluginGuide |

| R36 | Hardware practice, from a search summary and not the pages themselves ⚠, 2026-11-19: a label above or below a socket is hidden once a plug and cable are in; hardware builders leave about 10 mm clear at the top and bottom of a panel for the rails. The second does not bind software, but "design as if for hardware" (R33) is why the display and jacks keep clear of the screws | https://sdiy.info/wiki/Eurorack_panel_components |

| R37 | Surge XT for Rack: `surge-synthesizer/surge-rack` is GPL-3.0, last pushed 2025-06-28. Its helper library `surge-synthesizer/sst-rackhelpers` is MIT, header-only C++17, and documents itself in its README: a module advertises its main inputs and outputs (`NeighborConnectable_V1`), and its ports gain right-click items to connect to neighbours and to MindMeld MixMaster or AuxMaster. Found in use on GitHub by Surge XT, Airwindows (`airwin2rack`), BaconPlugs and `Doom2fan/OuroborosModules`: few adopters outside its authors. The user manual describes the modulation scheme (four CV inputs, arm one, knobs then show and set depth), three skins, a CLOCK input taking a pulse or a tempo voltage. ⚠ The manual does not describe how the live modulated value is drawn; that needs looking at the modules | https://github.com/surge-synthesizer/surge-rack · https://github.com/surge-synthesizer/sst-rackhelpers · https://surge-synthesizer.github.io/rack_xt_manual/ |
